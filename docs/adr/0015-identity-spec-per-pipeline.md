# Identity Spec per Pipeline — engine refuses defaulted renders

Hiviz Pipelines repeatedly shipped output that satisfied every R/Q/G rubric rule but read as "an animated div with a texture and a box-shadow" rather than as professional motion graphics. The diagnosis is not lack of taste in a fuzzy sense; it is lack of *decomposition*. "Real newspaper" is a six-dimensional claim — paper grain at multi-scale, halftone resolving at body cap-height, ink bleed at glyph edges, edge occlusion shadow, optical misregistration, camera defocus budget. A Pipeline that ships with one dimension implemented (a paper-colored fill with a texture overlay) and five defaulted renders the other five as their CSS-default form (box-shadow, square edges, no light interaction, no optical credibility), and the result is a div. The same failure shape applies to graphic Overlays — a lower-third chip with defaulted fill, edge, depth, light, motion, and frame-relationship is the structural definition of "animated div" — and to Annotations: a highlighter with no stroke-pressure-variation, no end-cap behavior, no registration offset reads as a colored rectangle, not a tool. Q5 in the quality rubric already asserts that "every element commits to an identity and obeys its physics," but Q5 is asserted, not operationalized — the Producer reads it, decides "the chip is a chip," and ships six defaults. We make decomposition a registration-time contract. Every visible Pipeline (Surface, Block, Annotation, Overlay) ships an **Identity Spec** at `src/lib/platform/pipelines/<layer>/<variant>/identity.ts` declaring a `kind` (`material` | `graphic` | `tool`), a one-line `claim`, and an explicit list of `dimensions`. Each dimension carries a one-sentence operational definition, a Pipeline-side implementation contract, and a Critic-side probe (script or named-observation). The Pipeline registration code refuses to accept a Pipeline whose Identity Spec ships with any dimension unimplemented or any dimension without a probe. The engine refuses to expose a renderer that would collapse to a defaulted approximation of its claim.

## Considered options

Reference-driven Critic step that asks the model to name production-grade references and grade the render against them (rejected: only as strong as the Critic's reach-for-references discipline, and the failure mode the user reports is the Producer *not knowing* the dimensions in the first place — adding a check at verify time doesn't change what the Producer authors). Per-Pipeline forbidden-lowest-effort patterns ("a paper Surface is rejected if it is a colored div with a single texture layer and a box-shadow") (rejected: enumerates negatives instead of positives — easy to avoid the named-bad version while shipping a different-bad version that wasn't enumerated). Soft Q5 rule as it stands today (rejected: Q5 already names the rule; the gap is operationalization, and asserting the same rule harder does not operationalize it). Two parallel Specs split by material claim vs. formal claim (rejected: more bureaucratic than the unified shape without giving anything the unified shape doesn't give — the `kind` field carries the same information and one mental model is cheaper than two).

## Consequences

Every existing Pipeline needs an Identity Spec written before the next release: `paper` / `plain-card` / `photo` Surfaces (kind: `material`), `highlight` / `underline` / `circle` / `strike` Annotations (kind: `tool`), `lower-third` / `washi-tape` Overlays (kind: `graphic`). The Pipeline registration entry point in `src/lib/platform/pipelines/<layer>/index.ts` calls a registration validator that walks every dimension on every Identity Spec and refuses Pipelines that are partial. The Critic's verification protocol (`docs/critic.md`) extends: after R-rules pass, the Critic walks each rendered element's Identity Spec dimensions and reports per-dimension observation (or numeric probe output) before reaching Q-rules. A new finding classification `identity-incomplete` joins `pipeline-bug` and `default-too-permissive` for the cases where a Pipeline registered, but the rendered output evidently isn't realizing one of its declared dimensions — that is a `pipeline-bug` at registration time but an `identity-incomplete` at render time. ADR-0001 (Critic sub-agent) remains in force; this ADR adds an inspection lane to the Critic's existing protocol rather than replacing it. The Q-rule anti-pattern list collides with Identity Spec dimensions in known places (ink-bleed-at-edges vs. "no chromatic aberration"; edge-occlusion-shadow vs. "no drop-shadow stacking"); ADR-0016 resolves that collision.
