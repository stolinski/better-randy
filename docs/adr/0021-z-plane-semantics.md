# Z is focal-distance, not world-space — depth as a sidecar to color

The motion-primitives library introduces Pipelines (`depth-of-field` Effect, `cursor-trail` Overlay, `instance-stack` Block) whose Identity Specs claim a `depth-treatment` dimension that the engine has no mechanism to satisfy. Today the engine composites Surface → Body → Annotation → Overlay back-to-front via alpha blending and that is the entire spatial story — there is no z value attached to a contribution, no depth target, and no way for an Effect like depth-of-field to know which slot to keep sharp and which to defocus. The temptation is to add world-space depth (a per-element z coordinate in some implied scene) and run a deferred-shading pipeline, but that buys properties Hiviz does not need (intersection of opaque geometry, refractive ordering, true ray-traced occlusion) at the cost of fighting the engine's transparency contract — alpha compositing of partially transparent contributions is order-dependent in a way deferred shading is not, and we cannot give up transparent WebM export. The motion-primitives plan paused on this in Phase 3.1 to pin the semantics before any Pipeline that depends on z ships. We pin two decisions. First, Z is a *focal-distance* scalar in [0, 1], where 0 means "in focus" and 1 means "maximum defocus." It is not world-space depth, not perspective z, not a distance from any virtual camera that could be moved. Effects that read it (`depth-of-field`, eventually `tilt-shift`, eventually atmospheric haze) treat it as a defocus weight directly; no projection math involved. Second, the depth target is a sidecar to the color target, not a participant in it. Every Pipeline that contributes to a frame writes color (alpha-blended back-to-front as today) *and* writes its z value into a parallel depth target. The depth target is sampled by post-process Effects; it never influences color compositing. Transparency export stays unchanged because compositing stays unchanged.

## Considered options

Treat z as world-space depth and add a depth-test stage to the rasterizer (rejected: depth-testing opaque pixels works against the transparency contract — partially transparent contributions composite by alpha, not by depth-test, and adding depth-test creates two parallel ordering rules that fight in any case where they disagree; the export's transparent WebM is the contract we cannot violate). Per-pixel z written into the alpha channel of an auxiliary target (rejected: alpha is already loadbearing in the color target and the engine's transparency export reads it directly; co-opting it for depth couples two semantically unrelated channels and breaks the moment a Pipeline needs a 0.5-alpha pixel that is also "in focus"). No z-value at all — Effects that need focal selection name the slot they keep sharp and defocus everything else as a binary mask (rejected: collapses depth-of-field's gradient bokeh into a sharp inside-edge / blurred outside-edge step, which is exactly the visual signature of the kind of cheap CSS effect ADR-0015's dimension claim is built to refuse). Per-Layer fixed z with no per-instance override (rejected: a Brief that places two Overlays in the same Layer cannot put one in focus and the other defocused, and the cursor-trail overlay specifically needs a per-instance z to sit above content while a body-text Block sits at the focal plane). Per-Pipeline override only, no Layer default (rejected: a Preset author has to declare a z value on every contribution by hand, and the default case — Surface in focus, Annotation slightly off, Overlay above — becomes verbose for no gain).

## Consequences

Per-Layer default z values pin into engine state: Surface = 0.0 (the focal plane by default), Body = 0.3, Annotation = 0.5, Overlay = 0.7, Cursor (the cursor-trail Overlay's z-Layer) = 0.9. A Preset may override per instance via an optional `z` field on the instance schema (gated to [0, 1] by Zod). The engine's gpu-host gains a depth target attachment at the same dimensions as the color target, cleared to 1.0 each frame and written by every contributing Pipeline at its current z value (a one-line fragment-shader write to the depth target alongside the color write). Effects that read z bind the depth target as an input texture; effects that do not read z stay unchanged. The depth target is single-channel f32, the same format the WebGPU spec gives for depth attachments used as sampled textures; it never affects color compositing, never participates in alpha blending, and is discarded after the Effect chain runs. The engine work (gpu-host depth target plumbing, effect-chain depth input, per-Pipeline depth write in shader sources) is deferred to a separate Brief alongside `depth-of-field` and does not land as part of the motion-primitives v1 library — only the semantics pin in this ADR. `text-3d` in the v1 library is unaffected because its depth handling is *internal* to its own render pass (an own depth buffer attached to its own render target for cylinder self-occlusion) and its output texture composites flat into the final color target like any other Block. `cursor-trail` in the v1 library uses the per-Layer default (z = 0.9) and does not declare a per-instance override, so it does not need the engine z-plane plumbing to land before it ships. `instance-stack`'s Identity Spec claims depth-treatment via lag-window propagation and an implied z-offset between instances; until the engine depth target ships, that dimension is honored visually through opacity ramp + spacing only, and the Identity Spec dimension notes the deferral. ADR-0020 (variants-as-data) interacts cleanly: a variant inherits its family's z behavior; a variant cannot opt into a different z-Layer than the family declares.
