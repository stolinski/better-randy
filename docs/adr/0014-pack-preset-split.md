# Pack/Preset split — aesthetic-agnostic Presets, render-time Pack resolution

The original `hiviz@1` Preset schema bundled the composition recipe (motion timings, content text, surface choice) with the aesthetic dress (palette hex codes, font family names, effect chains, surface chrome) into a single JSON document. As Hiviz's intended scope expanded from "Syntax channel overlay tool" to "general-purpose engine that ships one channel's Preset family today," the bundling became the structural cause of an overswing where every Brief, every brainstorm option, and every Critic verification defaulted through the Syntax aesthetic — because that was the only aesthetic the engine knew. ADR-0003 already claimed an aesthetic-neutral rubric split at the doc level, but the schema, the Critic spawn prompt, the brainstorm flow, and the canonical glossary in `CONTEXT.md` still encoded Syntax as the engine default. We split the Preset and the aesthetic structurally, not just doc-rhetorically. A **Preset** now declares motion + content + **Role** references only; an aesthetic **Pack** at `docs/packs/<slug>/` resolves Roles to concrete values — style roles to hex codes and font families, pipeline roles to Pipeline picks, chrome roles to effect chains. A Preset names exactly one Pack via a top-level `pack` field; the same Preset rendered against a different Pack produces a different look from one recipe. The engine pins a small Core Role vocabulary every Pack must implement (~8 style roles, ~6 pipeline roles); Packs may declare Pack-only Roles that only Presets bound to that Pack can reference. The existing Syntax aesthetic moves into `docs/packs/syntax/` and stops being privileged at the engine level.

## Considered options

Keep the bundled Preset and write a new Preset per aesthetic combination (rejected: aesthetic diversity multiplies the Preset count rather than the engine's expressive range, and the engine never proves it can render one recipe in multiple looks). Critic-invocation-declares-Pack with no Preset-level binding (rejected: Brief authoring and brainstorm have nowhere to anchor before the Preset exists, and a Preset's intent is lost if its Pack is only known at verify time). Default-Pack-at-engine-level with per-Preset opt-out (rejected: a default Pack is exactly the overswing this ADR removes — "Syntax-by-default" reads as Syntax-by-mandate to every downstream agent and the structural pull stays unchanged). Style-roles-only with Pipeline picks kept as direct references (rejected: caps each Pack at palette and font swaps, which leaves the substantive look — surface chrome, effect chains — unchangeable across Packs).

## Consequences

The Preset JSON schema changes shape: `typography.paperColor`, `marks.defaults.*.color`, `surface.type`, and the `effects.*` arrays become Role refs. A Pack manifest schema joins the engine, validated alongside the Preset schema. The existing 12 Presets need migration — hex codes, font names, and effect chains extract into the `syntax` Pack manifest, and the Preset bodies shrink to recipe-only Role refs. The Critic's spawn prompt (`docs/critic.md`) loads `docs/packs/<preset.pack>/aesthetic.md` instead of a global `aesthetic.md`; `aesthetic-miss` findings classify against the Preset's declared Pack, not against Syntax. The brainstorm skill asks which Pack before proposing Surfaces; Briefs declare their Pack as the first field. The channel-specific glossary terms in `CONTEXT.md` (Channel chrome, Mono signature thread, Collage card, Hard offset shadow, Registration jitter) move out of the core engine glossary into `docs/packs/syntax/aesthetic.md` — they are Syntax-Pack vocabulary, not engine vocabulary. ADR-0003 (aesthetic-neutral rubric split) remains in force; this ADR is what makes structurally true what that ADR claimed at the doc level.
