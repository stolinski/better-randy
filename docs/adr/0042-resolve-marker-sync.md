# ADR-0042 — Resolve marker sync: the edit authors the beats

Status: **Canon (v1 built; grammar amended to v2, 2026-07-16)**
Date: 2026-07-15
Builds on: [ADR-0040](0040-checklist-surface.md) (the checklist verification piece), [ADR-0032](0032-gui-agent-parity-authoring.md) (GUI↔agent parity), [ADR-0012](0012-effect-pack-context-progress-timestamp.md) (frame-determinism posture)

## Context

Supers pieces land in a real NLE. The Syntax edit is DaVinci Resolve at **29.97 NDF 1080p** (confirmed on TEMPLATE SESSION 2026 and episode 1023), but `transport.fps` was integer-only — a composition could only claim `fps: 30` against a 29.97 timeline, a standing timebase lie that guaranteed drift the moment a piece had to hit an edit-side moment. And placement was manual: author a piece, export it, then nudge it against the conversation by eye.

The editor already authors the beats — that is what markers are for. What was missing is a contract for Supers to read them: which markers are ours, what a marker means, how a marker's frame becomes a Preset timing, how the exported file gets back onto the timeline at the right frame, and how the editor sees that a group has been synced.

A verified SSH bridge to the edit machine exists (project memory `resolve-mcp-bridge-mbp`: Resolve Studio 21.0.2.4, scripting API, marker round trip proven).

## Decision

**The edit authors the beats; Supers projects them into the Preset at authoring time, frame-exactly, at the timeline's true rational rate.** The editor drops markers in **any color** — the grammar is color-blind on read (grammar v2, 2026-07-16): a group's **head** is the marker whose note names the piece (`supers <slug>`); its span is closed by an explicit **END** marker (a name whose last word is `END`), else by the head's dragged duration, else — degenerate, linted — by the last beat plus a handle. Every marker inside the delimited span is a **beat** regardless of color or name (the span is the claim), mapping to the composition's timed items in order (an item's `enter` for build-in pieces, `strike` for completion pieces); beat names carry the item text (`parseBeatLabel`: `<item> - Checked` strikes at the beat, `<item> - Add to list` enters at the beat, a bare label is a build-in enter). A sync reads the markers once over the SSH bridge (`scripts/resolve-markers.py`, a dumb JSON pipe), derives frame-snapped timings in pure TypeScript (`src/lib/utils/marker-sync.ts`: span → `durationSeconds`, beat frames → item starts, authored absolute lengths preserved — beats re-place motion, never re-speed it), and writes them into the Preset as explicit fractions. The engine gains the true timebase: `transport.fps` accepts the NTSC fractional literals `23.976 | 29.97 | 59.94`, each resolved internally to its exact rational (`30000/1001`) by `resolveFrameRate` (`src/lib/utils/composition-timing.ts`) — the literal is display, never math. Both exporters emit the rational `-framerate`; ProRes additionally stamps a non-drop `-timecode`, so the export (`<slug>__<TC>__<frames>f__v<version>.mov`) carries its own edit address. `scripts/resolve-place.py` (the second dumb pipe) imports it into a **Supers** bin, places it on a named **SUPERS** track at the head marker's record frame, and recolors the group **Mint** with `customData` (`supers-sync@1`: slug, beat index — head 0, beats 1-based, END −1 — version) — the editor sees "synced" at a glance, and re-syncs find their groups without re-parsing notes. The binding lives Resolve-side only: **WHAT in the preset, WHERE in the edit** — the Preset carries no edit anchor and stays episode-reusable.

## Considered options

- **A rational `{ num, den }` wire format for `transport.fps`** — rejected. Exactness does not require the wire format to be a fraction: the fractional *literals* keep every existing integer preset parsing unchanged, keep the GUI a picker of familiar labels (23.976 / 24 / 25 / 29.97 / 30 / 50 / 59.94 / 60), and keep agent-authored JSON humane, while `resolveFrameRate` supplies the exact rational to every frame computation, ffmpeg argument, and timecode label. A `{num,den}` field would migrate every preset and force fraction-editing UI for zero additional exactness. (Storing the true float `29.97002997…` was also rejected: it is not the conventional label anyone types, and invites float-equality bugs.)
- **A live Resolve link at render time** — rejected. Markers are projected **once, at authoring time**, into explicit Preset timings. A composition that resolves its timing against a running NLE is no longer self-contained: preview ≠ export whenever the edit machine is unreachable or the markers moved mid-render, violating frame-determinism ("the data model is the contract"). Re-sync is an explicit re-run of the projection; manual duration edits afterward stay governed by `rescaleCompositionTimings`.
- **An `editAnchor` field in the Preset schema** — rejected. Placement is edit-side state, not composition content: the same rundown ships in every episode at a different timecode. Binding in Resolve `customData` keeps the Preset episode-reusable, gives the editor's timeline sole ownership of WHERE, and survives preset re-authoring; an anchor field would be a second, staler source of truth and pure schema churn.
- **Any input-color scheme (a claimed color, or a taxonomy per piece kind / state machine)** — rejected; the claimed-Fuchsia variant was v1 canon but died after one real edit session (2026-07-16): hand-recoloring markers is a chore no editor performs, and the purple family (Fuchsia/Purple/Lavender/Rose/Pink) is indistinguishable at timeline zoom. Color is **output-only** — the head note plus span delimiters carry all meaning on read; the **Mint** recolor is the entire state display. Extra beats beyond the item count deliberately keep their input color — visibly unsynced.

## Consequences

- Existing integer-fps presets parse and render identically; the fps union is additive. The rate picker replaces the free-number FPS input (GUI parity, ADR-0032) — a loaded non-standard integer stays selectable, never silently rewritten.
- Frame math is rational everywhere it counts: export frame count/timestamps, `Timeline.stepFrames`, the frame counter, ffmpeg `-framerate`, NDF timecode labels (which tick at the nominal integer rate — that is what NDF means).
- Derivation is pure and tested (`marker-sync.ts` / `marker-sync.test.ts`); the Python scripts are I/O only, so every sync decision has a unit test and the bridge stays replaceable.
- Sync lint is advisory, not blocking: beat 1 before the card enter completes, beats out of recorded order, beat count ≠ item count (extras ignored; missing items keep authored spacing after the last synced beat), unclosed + undragged head (span falls back to last beat + 2.5 s with a warning), an END marker disagreeing with a dragged head duration (the END marker wins, warned).
- The Workspace exposes `window.__supersExport` (peer to `__supersTimeline`) so the agent-driven sync loop runs the *real* export path with `{ startTimecode, filename }`; the GUI button's behavior is unchanged.
- Resolve scripting realities, verified live on Studio 21.0.2.4 and encoded in the pipes: `SetSetting('timelineFrameRate')` requires a **string** value; `AddMarker` refuses an **empty name**, a **duration < 1**, and any frame **inside another marker's duration span** (programmatic fixtures add beats before the spanning head); marker `frameId` is relative to `GetStartFrame()` (normalize once — record frames are absolute); recolor is delete + re-add (restore on failure so a failed rewrite never eats the editor's marker).
- Agent-driven v1: no GUI marker browser. The `davinci-resolve` MCP server remains the interactive/inspection path; the deterministic loop is the two scripts over SSH.
- **Grammar v2 amendment (2026-07-16, dex `lrggqgvz`, real-editor feedback):** input color removed from the grammar entirely; explicit END markers close spans with precedence over a dragged head duration; every marker inside a delimited span is a beat; beat labels carry item text (`parseBeatLabel`); an agent-assembled group passes through `DeriveMarkerSyncOptions.group` (conversational selection — the customData receipt then makes it formally findable on re-sync); the END marker joins the Mint receipt as beat −1. Orphan lint now keys off customData, the only ownership signal color-blind reads retain. Proven shape: the ReachyMini "objective" group — start 4491 / 8 labeled beats / END 5701, mixed Purple+Blue.
