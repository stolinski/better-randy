# Brainstorm → Brief → Producer → Critic, with delete-on-ACCEPT

New Presets, Pipelines, and content domains enter the codebase through a three-agent lifecycle: a **Brainstorm** agent grills the user and writes a `Brief` under `docs/briefs/<slug>.md`; a **Producer** sub-agent reads that Brief with fresh context and authors the resulting Preset (plus any Pipeline / ADR work the Brief calls for); a **Critic** sub-agent verifies the Preset against the rubrics without ever seeing the Brief. The Brief is deleted in the same commit that lands the Critic's `ACCEPT`. For pipeline / domain Briefs that don't directly produce a Preset, the Brief declares a `verification preset` field; that Preset's `ACCEPT` is the delete trigger. The invariant is a one-way implication: *if a Brief exists in `docs/briefs/`, then its target (or verification) Preset is not yet Critic-`ACCEPT`-ed*. The converse does not hold — presets that shipped before this system landed have no Brief, and `/critic` runs against them work without one (`ACCEPT` is simply a no-op on the briefs folder). There is no separate backlog; ideas not yet grilled live outside the repo. The Brief template is flat — one markdown shape covers all three Brief kinds (`preset`, `pipeline`, `domain`) with sections skipped when n/a. See [`docs/briefs/README.md`](../briefs/README.md) for the template and the workflow.

## Considered options

- **Pure conversational ideation, no Brief artifact** (rejected: anything not immediately implemented evaporates; agent context isn't persistent enough to substitute for a written hand-off, and the "this needs to scale" concern is unmet).
- **Backlog file plus per-idea Brief** (rejected: introduces a second source of truth that drifts from `docs/briefs/`'s in-flight set; the "this is what I want to make next" thought lives in the user's head, not in a tracked file).
- **Briefs archived to `docs/briefs/shipped/` rather than deleted** (rejected: the active folder becoming a graveyard of shipped work is exactly the messiness the user wanted to avoid; git history is sufficient design record).
- **Brief folded into the Preset's `description` field on ship** (rejected: pollutes the runtime artifact with brainstorm rationale that's only useful in retrospect, and conflates "what this Preset is" with "why it exists").
- **Critic reads the Brief alongside the Preset** (rejected: violates [ADR-0001](0001-critic-sub-agent-verification.md)'s framing-flip; the Brief is *part of the conversation that produced the Preset* and would anchor the Critic into justification rather than adversarial probing. Intentional deviations the Critic needs to honor land in the Preset's `description` instead).
- **Same-session authoring rather than fresh Producer sub-agent** (rejected: parallels Critic's framing-flip rationale — the Brainstorm agent is biased by the conversation that produced the Brief; a fresh Producer treats the Brief as authoritative direction rather than living context).
- **Branched template (one file per Brief kind)** (rejected: maintenance overhead for three templates with substantial overlap, and forces the agent to pick a kind before sections are filled, which is wrong when a "preset" Brief retroactively reveals it needs a new Pipeline).
- **Pipeline / domain Briefs deleted on ADR merge rather than verification-Preset ACCEPT** (rejected: pipelines can land technically without proving they produce well-rendered output; tying the delete to a Preset's `ACCEPT` forces every engine change to ship with a demonstrating preset).
- **Brief-as-passive-capture (no agent push-back, no proposals)** (rejected: leaves anti-aesthetic ideas to be caught downstream by the Critic, wasting a full Producer + Critic cycle on ideas that should have been steered at brainstorm time).

## Consequences

`docs/briefs/` becomes the visible in-flight surface of the project. A directory listing answers "what are we currently building?". Two new slash commands enter the harness: `/brainstorm <slug>` (this skill's invocation; opens or extends a Brief) and `/author <slug>` (spawns a fresh Producer sub-agent that reads the Brief and writes the Preset and any engine work it declares). `/critic <slug>` is unchanged. The Brainstorm agent has a stronger stance than `/grill-with-docs`: it actively proposes options from `docs/aesthetic.md` § Motion Vocabulary, the existing Registry, and `docs/inspo/` at every decision point, rather than only capturing user-supplied direction. Pipeline / domain Briefs cannot ship without their declared verification Preset reaching `ACCEPT`, which means engine changes always land with a Preset that proves them out — the same pattern that ADR-0005 / ADR-0006 followed informally is now system-wide policy. The existing `docs/ideas/` (speculative product surface) and `docs/todos/` (open design questions) folders are unchanged in role; the boundary is: ideas are *might-build-someday*, todos are *decisions-still-open*, Briefs are *about-to-build*.
