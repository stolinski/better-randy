# Time-driven `EffectPackContext` for `ShaderPass.packUniforms`

`ShaderPass<TContent>.packUniforms(target, bounds)` (declared in `src/lib/platform/pipelines/types.ts`, run per-frame by the `ShaderPassDispatcher` per ADR-0010) saw only the per-target content and the rect — the timeline-driven scrub state was not threaded in. This is the same gap [ADR-0012](0012-effect-pack-context-progress-timestamp.md) closed on the effect-chain side, mirrored here for the surface + overlay shader-pass layer. Without it, no `SurfaceRenderer.shaderPass` (ADR-0008) or `OverlayRenderer.shaderPass` (ADR-0005) could animate from a `u_time` / `u_progress` uniform — the calling convention every time-driven shaders.com / ShaderToy port expects. We resolved this by widening `packUniforms` to `packUniforms(target, bounds, ctx: EffectPackContext)`, lifting `EffectPackContext` (`{ progress, timestamp }`) out of the effect-chain section of `types.ts` into a shared declaration both contracts now reference, and plumbing the value from the scrub through `ShaderPassDispatcher.apply()` → the internal compiled-pass closure → each pass's `packUniforms`. The two call sites in `Workspace.svelte` (live `renderAt` and export `renderFrame`) now compute the timebase once per frame via the existing `effectChainTimebase(timestamp)` helper and pass the same `{ progress, timestamp }` object into both `shaderPassDispatcher.apply({..., ctx})` and `effectChain.apply({..., ...ctx})`, so the surface shader pass, every overlay shader pass, and every effect-chain effect see byte-identical timebase values for a given frame — preview and export agree end-to-end.

## Considered options

- **Skip the parallel wiring; keep `ShaderPass` time-blind** (rejected: the ADR-0005 contract was authored explicitly so overlays could host imported shaders — and per ADR-0012 every shaders.com / ShaderToy import past the spatial-only minority needs a `u_time`. Leaving the contract time-blind locks the whole Overlay+shaderPass path into static-only effects, which is most of the reason the path exists).
- **Reuse `EffectPackContext` by name only, define a new `ShaderPassContext` type with extra fields** (rejected: there's no per-pass extra context worth distinguishing today; both contracts want exactly `{ progress, timestamp }`. Two parallel types would force every shader author to remember which name belongs to which contract, and a future field would have to be added to both anyway).
- **Read `timeline.time` from inside `ShaderPassDispatcher.apply`** (rejected: same reason as ADR-0012 — the export render path drives `renderFrame(frame, timestamp)` from a paused-by-progress export loop that never touches the live `Timeline` instance. Reading shared state would silently desync preview and export and break the frame-determinism contract the engine exists to guarantee. Threading from the caller is the only path that keeps both render paths agreeing pixel-for-pixel).
- **Add `EffectPackContext` as a separate parameter on each ShaderPass call site instead of inside `apply`'s opts** (rejected: the dispatcher's `apply` already takes a single opts object; threading a parallel positional argument would diverge from the existing shape and require every caller to update independently. One field on the opts object keeps the public surface coherent).
- **Move `EffectPackContext` into its own file** (rejected today: only `types.ts` declares either contract, the type is two lines and lives next to its consumers, and the AGENTS.md utility rule scopes new folders to `src/lib/utils/*` only. A future move into a shared platform types file is fine when a third consumer appears, but not for two co-located ones).

## Consequences

Time-driven shaders port one-to-one from shaders.com / ShaderToy into the surface + overlay shader-pass layer too — the same shape the effect-chain side already supports: declare a `progress` (or `timestamp`) field in `uniforms`, write `ctx.progress` into it inside `packUniforms`, reference `layout.$.uniforms.progress` in WGSL. The transparency contract holds: `packUniforms` only writes uniforms; the dispatcher's `loadOp: 'clear'` with `[0,0,0,0]` is unchanged. Frame-determinism holds and tightens: the surface shader pass, every overlay shader pass, and every effect-chain effect now read a single `{ progress, timestamp }` object computed once per frame in `Workspace.svelte`, so cross-layer time drift is impossible. The existing `newspaper-physics` consumer absorbs the signature widening with `_ctx` (it's spatial-only — halftone + ink bleed don't carry time). The first observable time-driven consumer is the new `shader-fill` Overlay registered at `src/lib/pipelines/overlays/shader-fill/` — a three-colour metaball mesh gradient whose three colour-centres drift along Lissajous curves driven by `progress`, registered in `src/lib/platform/pipelines/index.ts` alongside the existing overlays. `shader-fill` doubles as the first end-to-end exercise of the ADR-0005 `OverlayRenderer.shaderPass` path (until now declared but unused by any registered Overlay), so this ADR closes the loop on ADR-0005's deferred validation.
