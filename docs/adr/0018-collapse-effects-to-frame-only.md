# Collapse `LayerEffectChain` to a single frame-level chain

## Status

**Canon, with an execution-class refinement.** The flat composition-wide `effects[]` list remains current. Ordinary entries run as post-process passes; composition-owned Effects such as `depth-of-field` alter branch dispatch before the remaining chain. The decision-time prose below predates that registry split.

The `supers@1` schema modelled `effects` as a five-key object — `{ surface, body, annotations, overlays, frame }` — under the engine-architecture diagram (`engine-architecture.md` L317–363) where each composition Layer rendered to its own intermediate texture and that Layer's effect chain ran between Layers. The runtime never reached that shape: `Workspace.svelte`'s `renderAt` (L541–566) and `handleExport`'s `renderFrame` (L808–848) only feed `engineState.effects.frame` into `EffectChain.apply`. The other four keys accepted user input through the then-current global controls panel's `EFFECT_LAYERS` list and stored params in state, but no draw call consumed them. Two months of authoring produced 14 Presets; zero touched any non-`frame` key, and 12 left `effects` empty entirely. Meanwhile every concrete use case the architecture doc invoked for per-Layer chains migrated to a different route: substrate-intrinsic physics (newspaper halftone + ink bleed, future paper grain inside the card, future torn-edge fiber on collage cards) is carried by `SurfaceRenderer.shaderPass` / `OverlayRenderer.shaderPass` per ADR-0005, ADR-0008, ADR-0010 — per-Pipeline, declared by the renderer, not configured per-Preset. We collapsed the schema to `effects: Effect[]`. There is one composition-wide post-process chain, run after the final composite into the canvas. Per-target shader work — the load-bearing differentiator the channel aesthetic actually depends on — stays on `shaderPass` where it belongs.

## Considered options

Keep the five-key shape and wait for a real consumer to motivate the per-Layer texture rework (rejected: the schema field is dead state the Critic does not catch, the UI lies — an author can add Chromatic Aberration under Body, see sliders, save the Preset, and produce identical pixels — and the architecture diagram describes a runtime that does not exist. Carrying a contract the engine refuses to honor is exactly the load-bearing `when` anti-pattern ADR-0016 names). Build the per-Layer texture pipeline now (rejected: requires `PaperPipeline` to stop composing surface + body + annotations into one output texture, which conflicts with the focal-slot warp shader that reads all three together to apply magnify / isolate / tear-out — that warp would have to move to a final composite stage and an open design question opens about whether it warps pre-effect or post-effect Layers. Plus a rework of the overlay path so overlays render to `overlaysTex` instead of compositing via HTML-in-Canvas DOM upload — reversing the ADR-0005 architecture. Significant pipeline rewrite for a use case zero shipped Presets ask for). Keep a single-key wrapper `effects: { frame: Effect[] }` for non-breaking future expansion (rejected: we just rejected that future. The `frame` key only existed to discriminate from sibling Layers, and with no siblings the wrapper is dead syntax that every read site pays for forever. If a future engine ever does need per-Layer chains, ADR-0005 has already established that route is `shaderPass` on the renderer, not a layered effect chain — so even the recovered future does not resurrect this shape).

## Consequences

`LayerEffectChainSchema` is removed. `EngineStateSchema.effects` becomes `z.array(EffectSchema)` with default `[]`. `engineState.effects.frame` reads become `engineState.effects` reads at every call site. The `EffectLayer` type and `EFFECT_LAYERS` array in the global controls UI are deleted; `addEffect` / `removeEffect` in `engine-state.svelte.ts` lose their layer argument. The two Presets that use `effects` today (`newspaper-body-test.json`, `title-card-newspaper.json`) migrate from `"effects": { "frame": [...], ... }` to `"effects": [...]`. `verify-presets.ts` will catch any externally-authored `supers@1` Preset that still ships the object shape; failure is acceptable because no public Preset surface exists yet. `docs/CONTEXT.md`'s `Effect` definition changes from "per-layer post-process pass … compose into an effect chain on a target layer" to "composition-wide post-process pass run after the final composite into the canvas." `docs/engine-architecture.md`'s rendering diagram (L317–363) retires — the per-Layer texture flow it describes was never built and now never will be; AC-RP3 (paper-grain inside the card visible vs. on frame covering the viewport) reroutes from `effects.surface` to a `SurfaceRenderer.shaderPass` consumer on the `paper` Surface, paralleling ADR-0008's `newspaper-physics` consumer on the `newspaper` Surface; the L776 "Effects on Layers other than frame" known-follow-up is removed. `docs/todos/non-frame-effect-layers.md` is deleted (closed by this ADR). The diagnostic that surfaced this collapse — AI-authored Presets reading mid because authors aren't reaching for *any* effects, layered or otherwise, not because they need finer-grained ones — points to a separate, larger investigation (brief vocabulary, recipe coverage, Critic feedback, Pack manifest Role granularity) that opens as its own Brief; it is not addressed here.
