# Depth-of-field v1 — multiplane bokeh, not a per-pixel depth target

> **Status — Canon (v1 implementation decision). Refines [ADR-0021](0021-z-plane-semantics.md).** ADR-0021's Z *semantics* stand: Z is a focal-distance scalar in [0, 1] (0 = in focus, 1 = max defocus), per-Layer defaults (Surface 0.0, Body 0.3, Annotation 0.5, Overlay 0.7), per-instance override gated [0, 1]. What this ADR revises is the *mechanism*: not "every Pipeline writes its z into a per-pixel depth target," but a **2.5D multiplane bokeh** render — capture the composition as a few depth planes, blur each by its circle-of-confusion with a bokeh kernel, composite back-to-front.

ADR-0021 pinned a depth **target** written per-pixel by every contributing Pipeline, sampled by a `depth-of-field` Effect. That mechanism assumes separate per-Layer GPU passes. The real engine has none: `Composition.svelte` nests `SurfaceMount` *and* `OverlayMount` inside one `.composition` element, and the pipeline rasterizes that whole element into a **single flattened DOM texture** via `copyElementImageToTexture` — which captures colour only. There is no per-pixel depth to write or read; the depth-target mechanism does not survive contact with the architecture (the same way ADR-0022's live dual-tree didn't, resolved by [ADR-0026](0026-transitions-v1-snapshot-and-wipe.md)).

We implement DOF the way motion-graphics DOF is actually done — **multiplane**. The composition is captured as a small set of depth planes: the Surface plane, and each Overlay at its z (ADR-0021's per-Layer default, optionally overridden per-instance). Each plane is blurred by its **circle of confusion** — `coc = aperture × |planeZ − focusZ|` — using a **disc-shaped bokeh kernel** (sample a disc of radius `coc`, not a gaussian) with **highlight bloom** (bright samples weighted up so highlights bloom into bokeh discs, the signature photographic tell). Planes composite **back-to-front**, focal plane sharp, foreground planes bleeding slightly over the subject. The photorealism is carried by the bokeh kernel — CoC scaling, disc/aperture shape, highlight bloom — not by depth granularity.

This reaches the realizable photoreal ceiling for Supers because its elements are **flat**: a card, a word, an overlay each sit at one uniform depth, so per-element depth is identical to per-plane depth. A per-pixel depth target would only add fidelity for elements with *continuous internal depth* — a perspective-tilted card, `text-3d`'s self-occluding cylinder — which are rare and out of v1 scope.

## Considered options

- **Per-pixel depth target, written per Pipeline (ADR-0021 as written)** (rejected for v1): physically the most general, but requires per-Layer GPU passes that don't exist — Surface and Overlays are one flattened DOM texture, and `copyElementImageToTexture` is colour-only, so there is nothing to write depth from or to.
- **Z-map DOM** (parallel render where each element's colour encodes its z, captured to a depth texture) (rejected for v1, kept as the upgrade path): yields genuine per-element / continuous depth and pairs with the same bokeh kernel — but for *flat* graphics every element's z is uniform, so it does not beat multiplane on the actual content, at much higher complexity (a fragile parallel restyled DOM). It becomes worthwhile only when continuous-depth elements (perspective cards, `text-3d` internal depth) need defocus *within* one element.
- **Positional / tilt-shift DOF** (blur by distance from a screen-space focal band) (rejected): no depth at all — blurs by screen-Y, the "fake DOF" look that reads as a filter, not a lens; it is exactly the step-mask ADR-0021 refused.
- **Multiplane bokeh** (chosen): depth-separated planes + a real bokeh blur. The 2.5D technique AE / title-sequence DOF uses; photoreal for flat layered graphics; reuses the transition snapshot capture machinery (`renderCompositeTo` to separate textures).

## Consequences

The DOF is a new render stage, not a post-process over the single composite: it needs the planes *separated*, so it captures the Surface element and the Overlay element(s) into their own textures (the capture-to-texture seam built for ADR-0026) rather than reading the merged frame. A `depth-of-field` Effect then blurs each plane by its CoC and composites. The Effect's params are authored: `focusZ` (the in-focus plane, default = Surface's z), `aperture` (blur strength / max CoC), and bokeh shape (disc; optional N-blade aperture polygon and an anamorphic stretch as later knobs). Per-Layer z defaults from ADR-0021 stand; the overlay schema gains an optional `z` in [0, 1]. The transparency contract holds end to end: each plane is the normal premultiplied composite of its content, the bokeh shader preserves alpha, and the planes composite premultiplied, so the export is a single transparent WebM with the defocus baked in. v1 planes are Surface + Overlay(s); per-element and continuous-depth defocus via the z-map remain the documented upgrade. The engine work (separate-plane capture, the bokeh DOF Effect, the schema z field, a demo preset) is tracked as the depth-of-field epic in [`../roadmap.md`](../roadmap.md) / dex.
