# Identity Spec dimensions declare `implementation` OR `via-pack` — the seam between ADR-0014 and ADR-0015

## Status

**Canon, refined by ADR-0023 and ADR-0024.**

> Refined by [ADR-0023](0023-pack-is-appearance-only.md) (only the four _appearance_ dimensions may be `via-pack`; motion-form and frame-relationship are always intrinsic — motion never concedes to a Pack) and [ADR-0024](0024-role-resolution-core-fallback.md) (a `via-pack` Role resolves with per-Pipeline-override → core-vocabulary fallback).

ADR-0015 (Identity Spec per Pipeline) and ADR-0014 (Pack/Preset split) were merged on the same wave but never reconciled at the seam where they meet. ADR-0015 says every visible Pipeline declares the dimensions of its claim and the registration validator refuses Pipelines whose Identity Spec ships with any dimension unimplemented. ADR-0014 says aesthetic decisions (fill, edge, chrome) extract into Pack Roles so the same Preset rendered against a different Pack produces a different look. The collision is structural: a `graphic`-kind Pipeline like `lower-third` claims six dimensions (fill-treatment, edge-treatment, depth-treatment, light-treatment, motion-form, frame-relationship) and only owns one or two of them intrinsically — its motion-form (slide-up + reveal) and arguably its frame-relationship (anchored to a frame corner). The other four are _aesthetic_: fill is a hex code or a material, edge is a stroke recipe, depth-treatment is a shadow rig, light-treatment is whether the chip carries directional sheen. Per ADR-0014 those are Pack Roles; per ADR-0015 they are Pipeline dimensions the registration validator gates on. With no clause that bridges the two, a Pipeline either hardcodes its fill (violating ADR-0014's structural-not-doc-rhetorical split) or leaves the dimension unimplemented (violating ADR-0015's registration gate). Both are wrong. We add a third form to the Identity Spec dimension contract: a dimension declares either an `implementation: <code-pointer>` _or_ a `via-pack: <role-name>`. The registration validator accepts both forms. The Pack manifest validator (new in this ADR) confirms every `via-pack` role referenced by a registered Pipeline resolves in the active Pack manifest. `material`-kind Pipelines (paper, newspaper) keep declaring all dimensions via `implementation` — paper grain is not a Pack decision, it is what the Pipeline _is_. `tool`-kind Pipelines (highlight, underline, circle, strike) keep declaring tool-physics dimensions via `implementation` for the same reason — pressure variation and end-cap behavior are tool intrinsics, not aesthetic dress. `graphic`-kind Pipelines (lower-third, chips, plates, motion-led Surfaces) declare 1–2 structurally-intrinsic dimensions via `implementation` (usually motion-form, sometimes frame-relationship) and the remaining 4–5 via `via-pack`. The seam closes.

## Considered options

Hardcode the four aesthetic dimensions on each graphic Pipeline and live with the ADR-0014 violation (rejected: forces a per-Pipeline rewrite every time a new Pack ships, which is the structural pull ADR-0014 was specifically built to remove; one channel's aesthetic re-becomes the engine default). Allow graphic Pipelines to ship with the four aesthetic dimensions unimplemented and disable the registration validator for `graphic` kind (rejected: collapses ADR-0015's gate exactly where the failure mode it was built to catch shows up — `graphic`-kind is where "animated div" lives; turning the gate off on that kind is the same as not having the gate). Move the four dimensions out of `graphic`-kind Identity Specs entirely so a graphic Pipeline only declares motion-form and frame-relationship (rejected: an Identity Spec that doesn't name fill/edge/depth/light cannot be probed by the Critic against the active Pack's resolution of those Roles — the Critic loses the inspection lane ADR-0015 added). Two-tier dimension structure with `intrinsic` and `aesthetic` keys per Pipeline (rejected: the `via-pack` clause encodes the same distinction more cheaply — a dimension that resolves through a Role _is_ the aesthetic-tier dimension, and a separate key tree duplicates the information without giving anything the unified shape doesn't give).

## Consequences

**Implementation note (2026-07-13).** `scripts/verify-presets.ts` now runs `validateIdentityRegistry` against the reference Pack as part of the normal machine gate; this contract is no longer boot-only. The same command runs the broader Pack manifest validator for every registered Pack before any pixel review.

The `IdentityDimension` type at `src/lib/pipelines/surfaces/newspaper/identity.ts` (and any sibling location once the type lifts to a shared module) extends from `{ name, definition, implementation, probe }` to a discriminator: a dimension carries either an `implementation: string` field or a `viaPack: string` field, never both, and the `probe` field stays required in either case — Critic-side verification doesn't change because the Pack's resolution still has to be observable in pixels. The registration validator wired in Phase 1.4 walks every dimension on every registered Identity Spec: a dimension with `implementation` validates as today (the code pointer must resolve, but cheaply — string presence at registration, deeper verification deferred to the Critic); a dimension with `viaPack` validates that the named role appears in the active Pack manifest. A new Pack manifest validator runs at engine boot (or at the first render call, behind a one-time gate): it walks the registry of registered Pipelines, collects every `viaPack` reference, and refuses to start if any of them does not resolve in the configured Pack. The 23 Identity Spec backfills in Phase 1.3 use the new shape from the start; the existing `newspaper` Identity Spec stays unchanged because every one of its dimensions is intrinsic to the material claim. ADR-0014's Pack manifest schema gains a structural requirement — it must enumerate the Roles that satisfy every Pipeline's `viaPack` references — and the `syntax` Pack folder migration in Phase 1.2 ships that enumeration as its first published manifest. The original motion-primitives plan estimated the Identity Spec backfill cost at "23 × 6 dimensions"; with this clause the cost is "23 × 1–2 intrinsic + Pack manifest," and the structural reason ADR-0015's gate would otherwise stall the variants pattern (every variant carrying its own copy of four aesthetic dimensions) is removed. ADR-0020 (variants-as-data) inherits the same shape — variants share their family's Identity Spec, which means a family's `via-pack` declarations are inherited by every variant; a variant cannot opt out of one of its family's dimensions and a variant cannot add a new dimension that the family does not declare.
