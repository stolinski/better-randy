# Compose-pipeline invocation for `SurfaceRenderer.shaderPass` and `OverlayRenderer.shaderPass`

## Status

**Canon.**

The declarative `shaderPass` field added to `OverlayRenderer` by [ADR-0005](0005-overlay-renderer-shader-pass.md) and to `SurfaceRenderer` by [ADR-0008](0008-newspaper-surface-pipeline.md) was authored but never invoked — the `newspaper-physics` WGSL was complete and registered on the newspaper Surface, but the compose-pipeline ran the surface's output texture straight into the per-frame effect chain with no intermediate pass. We resolved this by adding a `ShaderPassDispatcher` to `src/lib/platform/pipelines/shader-pass-runner.ts` that compiles each declared `ShaderPass<T>` once (reusing the same bind-group shape the effect-chain executor uses — `inputTexture`, `samp`, `uniforms`) and runs the surface + overlay passes in document order between the surface pipeline's render and the per-frame effect chain. The dispatcher owns two ping-pong intermediate textures so a sequence of passes (surface first, then any overlay passes) can read the previous pass's output. `Workspace.svelte` builds the per-frame dispatch list from `getSurfaceRenderer(...).shaderPass` plus a walk of `engineState.overlays`, packs uniforms via each pass's `packUniforms(target, bounds)` (surface bounds = full canvas rect; overlay bounds measured against `compositionElement.getBoundingClientRect()` with a position-derived fallback at first paint, lifted into the new `src/lib/utils/overlay-bounds.ts` helper), and feeds the post-shader texture into the existing `EffectChain.apply` call. Both the preview render path and the export render path go through the same dispatcher so AC-D1 still holds (one render function; export inherits shader passes).

## Considered options

- **Build per-renderer invocation inside the surface and overlay pipelines** (rejected: it would force every consumer of `*Renderer.shaderPass` to re-implement the bind-group + uniform-buffer plumbing the effect-chain executor already factored out, defeating the point of declarative `ShaderPass<T>`. Centralised dispatch is the equivalent of the effect-chain runtime — same calling convention, same uniform plumbing, just keyed to per-target instead of per-effect).
- **Reuse `EffectChain` directly** (rejected: `EffectChain` finds compiled passes by `EffectRenderer.type` string lookup against the registry; `ShaderPass<T>` is declared inline on the *renderer* and carries no `type` discriminator. Forcing a string id onto each shader pass would be a contract change that buys nothing — the renderer identity already keys the cache, via `WeakMap<ShaderPass, CompiledShaderPass>`).
- **One intermediate texture instead of ping/pong** (rejected: when a Preset eventually declares both a surface `shaderPass` and an overlay `shaderPass`, the overlay pass needs to read what the surface pass wrote. WebGPU forbids a draw reading and writing the same texture, so a single intermediate would deadlock the second pass).
- **Defer overlay-side dispatch until a real consumer ships** (rejected: ADR-0005's `OverlayRenderer.shaderPass` is part of the engine contract today even though no overlay declares one yet. Wiring only the surface path now would leave a known-incomplete dispatcher in the engine; the overlay walk is a four-line loop that costs nothing at runtime when no overlay declares a pass).
- **Eager-compile shader passes at host init instead of first-frame** (rejected: shader-pass compilation is one-shot per pass identity and only fires when the Preset routes through a renderer that declares one. Eager compilation would force every host to compile every registered shader pass, including ones never used by the active Preset).

## Consequences

Renderers can declare `shaderPass?:` on `SurfaceRenderer` (ADR-0008) or `OverlayRenderer` (ADR-0005) and the engine runs it; the WGSL fragment-body calling convention is the same as `EffectPassDefinition.fragmentBody` (`in.uv`, `inputSample`, `layout.$.uniforms`) so authors fluent in one are fluent in the other. The transparency contract holds: every intermediate render target uses `loadOp: 'clear'` with `clearValue: [0, 0, 0, 0]` and the canvas context stays at `alphaMode: 'premultiplied'`. Frame-determinism holds: uniforms are packed once per frame from the timeline-driven target state, no wall-clock reads. The dispatcher is allocated alongside the GPU host and disposed with it, so the two intermediate textures' lifetime tracks the canvas-size lifetime; resizing the canvas requires re-creating the dispatcher (today the host already re-creates on canvas change, so no new lifecycle work). The first observable consumer is `title-card-newspaper.json` (the newspaper Surface's halftone + ink-bleed shader now fires); the second future consumer is the not-yet-authored `tear-edge` shader on collage-card overlays per ADR-0005, which lands as one new file under `src/lib/pipelines/shader-passes/` plus one `shaderPass:` line on the consuming overlay's `index.ts` with zero engine work.
